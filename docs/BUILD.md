# Reproducible source build

The source manifest binds each allowed file by SHA256 and original blob id. The selected engine is TensorFold v1.2.8 plus the measured hybrid delta and exactly two measured observation overlays. No newer main or tile32 repair is substituted. Seven unrelated DeepSeek contract-test checkpoint/reference payloads are deliberately excluded; those unrelated tests cannot be run from this export. The source manifest records exact shipping hashes and distinguishes the selected lab bytes from the notice-only packaging changes below. The portable wrappers are separate from engine source.

Use Zig0.17.0 (compiler SHA2567c61539af19fa4082c94848f1c2b57b89e76dc6cfd5bd4c57764c3caf8f82272), CUDA13.0.1 development toolkit, SM120+121, native-fp-decode=false, small/strip, -j1, Linux GNU2.28 x86_64 attention and aarch64 expert. Build flags are in build.sh. CUDA and verbs are dynamically provided by the user's host. Use rdma-core v50 headers; Ubuntu libibverbs-dev50.0-2ubuntu0.2 archive SHA256fb409dc756c1697a83683e43a3ca78cb9eabbc24605391808252b8d8bedf54fc was the original header input. Set ZIG_BIN, BUILD_DIR, ASSET_DIR, CACHE_DIR and RDMA_HEADERS explicitly when needed.

build.sh assets compiles the native catalogue then its separate tp_mailbox from mailbox.cu/roce_device.cuh; roce_gather is NOT its replacement. No CUDA objects are supplied. The no-device packaging build reuses the already source-qualified117 local CUDA assets, not a fake compiler or empty image. A from-scratch rebuild of all117 is not claimed by this export. Linkage/ABI/driver/device execution and performance remain separate from successful compilation.

Structured-output library: supply an actual xgrammar v0.2.8 Git checkout at97787376faee5ed8466cfad57c99855e4ce2f6aa with DLPack submodulebbd2f4d32427e548797929af08cfe2a9cbb3cf12 and picojson. Run from engine: `zig build grammar -Dxgrammar=/absolute/xgrammar --prefix /absolute/install`. It installs native/lib/libtfgrammar.so beside native/bin. Do not fake git describe or copy another version's library. This same shared grammar implementation previously passed52/52 consumers; no claim of rebuilding or redistributing the original library here. Keep it at an owner-controlled, non-group-writable path, and stage the resulting install tree so render --install points at it. Expert executables install in bin, attention in native/bin; assets go in assets. No global/root install is scripted.

Portable wrapper tests: `python3 -m unittest discover -s tests -v`. Engine affected CPU consumers: `./build.sh cpu-test`. This is a targeted profile build/test contract, not an all-families test distribution. `build.sh expert-host` additionally compiles an x86 expert for running both generated expert JSONs with --check before any device/model access. The ARM executable is cross-compiled and ELF-inspected; it cannot be executed on x86 without separate emulation.

## Notice-comment successor identity

The public packaging adds per-file change notices. Those source files are not byte-identical to the hardware-tested engine blobs described above. Original hashes/blobs are retained separately as hardware_tested_sha256/hardware_tested_source_blob in the successor source manifest. Only leading comment statements are added by this notice patch; no executable source token changes are intended. That does not establish compiled-binary identity or device qualification of the successor bytes. Do not relabel the original tested head or binaries.
