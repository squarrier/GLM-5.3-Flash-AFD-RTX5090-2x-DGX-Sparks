## At a glance

TensorFold v1.2.8 with attention on an RTX 5090 and routed experts split across two DGX Sparks over native RoCE. The 5090 keeps the index keys on the GPU; the active BF16 KV history is pinned in the same machine’s system RAM. The lab run attached 7,496 of 7,500 requested pages and held eight independent 479,232-token prompt-plus-output windows near capacity. The profile uses 16-bit dense layers and output head, BF16 expert inputs, ordered FP32 weighted returns, 32 verifier rows, a 16-row attention tile and built-in checkpoint MTP (no DFlash2). See [recipe.json](https://github.com/squarrier/GLM-5.3-Flash-AFD-RTX5090-2x-DGX-Sparks/blob/bbc563e708f5eb0c2c2a1054c61b62af454bb45f/recipe.json), [source manifest](https://github.com/squarrier/GLM-5.3-Flash-AFD-RTX5090-2x-DGX-Sparks/blob/bbc563e708f5eb0c2c2a1054c61b62af454bb45f/manifests/engine-source.json) and [mechanisms](https://github.com/squarrier/GLM-5.3-Flash-AFD-RTX5090-2x-DGX-Sparks/blob/bbc563e708f5eb0c2c2a1054c61b62af454bb45f/docs/MECHANISMS.md).

The engine includes the selected lab implementation with its two measured observation overlays. The public source manifest distinguishes original measured blobs from notice-only changes. The original portable packaging was CPU-qualified, **not a device-qualified deployment**. It imports no private history, automation or infrastructure. Do not substitute newer upstream or tile32.

## Install and build

Prerequisites: Linux, Python3, Zig exactly0.17.0, CUDA13.0.1 nvcc for SM120/121, rdma-core v50 build headers/runtime and matching NVIDIA driver. XGrammar v0.2.8 source revision97787376faee5ed8466cfad57c99855e4ce2f6aa is an external grammar build input; no compiler, GPU objects, library, weights or proprietary driver is redistributed. Check [BUILD.md](https://github.com/squarrier/GLM-5.3-Flash-AFD-RTX5090-2x-DGX-Sparks/blob/bbc563e708f5eb0c2c2a1054c61b62af454bb45f/docs/BUILD.md) before downloading. No install script runs sudo, SSH or changes host settings.

```sh
./build.sh cpu-test                 # actual selected engine CPU regressions
./build.sh assets                   # compile source kernels using your CUDA toolkit
./build.sh attention                # x86_64 server with your compiled assets
./build.sh expert                   # aarch64 expert executable
python3 scripts/render.py --out ./runtime --session YOUR_NONZERO_32_HEX_SESSION
```

Obtain the exact checkpoint independently from its author; [CHECKPOINT.md](https://github.com/squarrier/GLM-5.3-Flash-AFD-RTX5090-2x-DGX-Sparks/blob/bbc563e708f5eb0c2c2a1054c61b62af454bb45f/docs/CHECKPOINT.md) records the repository/revision and obligations. No automatic weight fetch or conversion. Edit generic inputs via renderer flags (`--help`): shared session, isolated fabric address, verbs device, model path, runtime/binary/auth paths. Use the same settings on all three hosts. Generated files are exclusive and must never overwrite a live generation. The renderer opens no weights, devices or secrets.

## Start / stop — local foreground only

```sh
./start.sh runtime/attention.launch.json --ack-local-resources
# On each expert host, instead use expert0.launch.json or expert1.launch.json.
# Another terminal on that same host:
./stop.sh runtime/attention.launch.json
```

A real operator must separately verify device vacancy/ownership, physical floors, fabric, payload integrity and legal terms. GB10 unified memory is not constrained safely by Docker RAM limits; never run a second GPU tenant. No host discovery, SSH, fleet orchestration, daemon/service modification or lease borrowing is included. The launcher owns only its child, uses a creation-bound pidfd and a same-user local Unix control socket, forwards TERM once, never KILLs/restarts, and retains ownership until the child exits. Stop must fail closed on unknown state. The API defaults loopback and requires an owner-controlled mode0600 key file; provision it yourself, never put a secret in git/argv/env. Rank/RDMA control is unauthenticated: isolate and firewall the fabric, never expose either listener publicly.

**Exact measured diagnostics:** the selected environment retains `TF_GLM_QUALIFY_524X8=1` and the measured observation overlay. Near-cap qualification can deliberately hold histories for up to5400s; those intervals are not production latency. This is a lab recipe, not an unattended production default. Disabling diagnostics would be an explicit unmeasured profile delta.
